Checked 2026-10-01T12:33:15.510030Z. Covers all 56 recipe definitions and 23 application definitions, including built-in dependencies.

Upstream documentation review, not live container deployment certification. Planning entries require release-specific design before deployment.

Environment names retain upstream case. New Jellyfin and Immich access defaults are root origins; old seeded defaults are corrected without overwriting explicit custom exposure. Health verification rejects 404 and other failed HTTP responses. Existing containers and user-selected image tags are not automatically recreated.

## Updating the catalog

Re-check the primary documentation for the exact image variant and selected release when changing ports, environment names, mounts, dependencies, health paths or proxy behavior. Update recipe guidance and dated references in both private and public catalogs, then update the reviewed file SHA-256 values in `config/home-lab/documentation-review.json`. The regression check deliberately fails if reviewed definitions change without refreshing this record. A rolling image tag can change independently of LMS; consult release-specific docs before deploying and verify the configured browser entry point after starting.

## Browser entry points and repair verification

The server origin, proxy base path, browser entry point and dedicated health endpoint are separate settings. The application catalog stores documented browser entry points in `exposure.clientAccess.browserEntry`, with their documentation source. Jellyfin's `/web` comes from its [networking documentation](https://jellyfin.org/docs/general/post-install/networking/); it is not an application-name branch in the URL resolver.

A saved Open-link override takes precedence over deployed Docker labels (`com.linuxmadesane.browser-url`, `net.unraid.docker.webui`, or `homepage.href`), then the documented catalog setting. Compose drafts and newly created containers carry the declared browser entry as metadata. Project and documentation URLs are not browser entry points. Missing browser metadata is shown as unconfigured rather than inventing an app path. Paths, query strings, fragments and configured proxy prefixes are preserved when selecting the LAN or published origin. Changing an Open link does not recreate a container.

Container health uses the declared health check. A failed proxy-root request must not overwrite a successful dedicated health response or cause a working container to be recreated. Group repair refreshes current health, checks the shared VPN gateway first and verifies actual health after repair. Missing containers retain saved configuration, volumes, endpoint records and deployment membership; only explicit removal deletes their managed records.
